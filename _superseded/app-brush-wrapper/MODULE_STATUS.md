# Nimbus3D module status

Honest per-module state after integration. Status values:
**REAL** (works as written), **PARTIAL** (real core + labelled stub/limits),
**STUB** (typed placeholder only). Nothing here is marked working that is not.
Nothing is build-verified on this machine (no macOS/Xcode/Rust toolchain here);
the CI workflow (`.github/workflows/ios.yml`) compiles and archives it.

## Integration changes applied

- **Collision fix:** two `CaptureBundleStore` types (Pipeline public + Capture internal) compiled into the one Swift module. Renamed the Capture-owned loader to `CaptureBundleReader` (only self-referenced) so the build has a single `CaptureBundleStore` (Pipeline's).
- **App wiring:** `NimbusApp` now mounts `CaptureRootView` / `ProcessRootView` / `LibraryRootView` and calls `NimbusServices.registerAll()` at launch to inject `BrushSplatTrainer`, `SplatMeshExtractor`, `HDRIAssembler`, `NimbusAssetExporter`, and (via `MaterialsModule.register()`) the Materials services.
- **project.yml:** documented the single-target compile model; excluded the Rust crate/build-script/docs from the app compile; kept `.metal` shaders and the ambientCG resources as individual (flattened) resources so `MaterialLibrary` bundle lookups resolve.
- **Two Library screens coexist** (Pipeline `LibraryRootView` reads `asset.json`; Export `ExportLibraryView` reads `manifest.json`). Both scan `Documents/Exports`; the app mounts the Pipeline one because the orchestrator persists `asset.json`. Left both in place (no faked behavior, just redundancy).
- **No `Sources/Core/Contracts.swift` change:** every conforming type already matched the contract signatures; the only fix needed was the name collision above.
