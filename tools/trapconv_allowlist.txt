# trapconv allowlist
#
# Float-to-integer conversions that `tools/trapconv.py` flags and that a person
# has opened the source for and judged safe. One `File.swift:line  # reason`
# per line. Anything the detector finds that is NOT on this list fails CI.
#
# WHY THIS FILE EXISTS
# `Int64(someFloat)`, `Int32(...)`, `Int(...)`, `UInt8(...)` and friends are
# TRAPPING conversions in Swift. They kill the process, in release as well as
# debug, on NaN, on infinity, and on any finite value outside the destination
# type's range. Memory is irrelevant, which is why the owner's crash report
# said "even with RAM free". The same three lines were found in five separate
# files. This list is the record that every remaining one has been looked at.
#
# THE QUESTION ASKED OF EACH LINE
# Can the value reaching this conversion ever be NaN, infinite, or outside the
# destination range? A world position, a projected pixel, a pose, a division
# whose denominator can be zero, a sqrt/log/acos, or anything read back off
# disk means YES until proved otherwise.
#
# THE SUBTLETY
# Swift's `min(x, y)` is `y < x ? y : x` and `max(x, y)` is `y >= x ? y : x`.
# NaN compares false against everything, so the SECOND argument is absorbed and
# the FIRST propagates:
#
#     UInt8(max(0, min(255, x)))          -> 255 when x is NaN.  SAFE.
#     UInt8(min(max(x * 255, 0), 255))    -> NaN when x is NaN.  TRAPS.
#
# `simd_clamp`, `simd_min` and `simd_max` are the fmin/fmax family and DO
# absorb NaN from either side, which is why `TrainerMath.clamp` and
# `SmartMath.clamp` (both `simd_clamp`) are safe and hand-written `Swift.min`
# / `Swift.max` pairs have to be read argument by argument.
#
# LINE NUMBERS
# The detector's own line numbers, which moved when the guards landed. It used
# to lose a newline on every Swift multi-line-string continuation (`\` at end
# of line), which put the tail of MetalSplatTrainer.swift fifteen lines out and
# made entries here point at innocent code. Fixed in tools/trapconv.py on
# 2026-09-06; re-run `python tools/trapconv.py --list` after any edit and
# refresh the numbers rather than guessing at them.
#
# Curated 2026-09-06, 65 entries, every one read in the source.
